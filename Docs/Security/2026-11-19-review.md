## Findings

### SEC-004 — Medium: spreadsheet formulas in Ledger report exports

The original `exportReport` in [Ledger's browser interface](../../AITest/wwwroot/ledger-reborn/2026.10.12-preview.1/app.js) quoted CSV fields but left formula-like text active. A synthetic bank JSON description of `=1+1` was imported and classified into account `6300`; the resulting journal memo reached a report and was exported as an unprotected formula cell. Exploitation requires attacker-influenced input, report export, and opening the CSV in spreadsheet software. No spreadsheet formula was executed during this review.

The local fix prefixes dangerous **string** cells, including headers, with an apostrophe before CSV quote escaping. It handles ASCII and full-width formula initiators, leading whitespace/control characters, and leading tab/CR/LF. Actual numeric values, including negative integer-cent amounts, retain their representation. Stored records and report data are unchanged. Ordinary text, quoted delimiters, Unicode, empty values and the UTF-8 BOM are preserved. The export notice explains the prefix because it becomes part of the CSV text for downstream consumers.

[The regression](../../scripts/test-ledger-csv-export.mjs) executes the actual export callback, captures the download and parses the CSV. It checks dangerous headers and values, embedded quotes/separators/newlines, all three supported report result shapes, unchanged source data and negative numbers. An independent synthetic import-to-export reproduction is retained locally at `.tools/security-20261119/csv-formula-repro.mjs`.

This is a defense at the initial CSV export boundary, not a guarantee for every spreadsheet application's import or save/reopen behavior. [OWASP's CSV guidance](https://owasp.org/www-community/attacks/CSV_Injection) documents those compatibility limits. CSV is not a lossless format for preserving spreadsheet cell types.

### SEC-R1 — Informational maintenance warning: PDF dependency

RustSec reports `chrono 0.4.45` as unmaintained under [RUSTSEC-2026-0543](https://rustsec.org/advisories/RUSTSEC-2026-0543.html). The chain is `aicraft-pdf` → pinned `pdfcraft-cos 0.15.0` → `chrono`. The advisory identifies no patched version and is classified as informational, not a known vulnerability.

The warning remains visible in the audit; no ignore rule or severity suppression was added. Replacing it requires an upstream PDF dependency change and corresponding PDF compatibility validation. That migration is follow-up work, rather than an unverified change to the pinned PDF engine during this review.

### SEC-R2 — Existing shared-origin storage risk

The upstream editors, local Ledger books and local Tax records share the GitHub Pages origin. Origin boundaries do not isolate one editor's JavaScript from another editor's browser storage. A compromised or malicious editor on that origin could access locally stored sensitive records. The separate bank origin protects bank sessions from this shared editor origin; it does not isolate the local books and returns from other editors.

Moving sensitive local tools to a separate origin remains an architectural follow-up. It requires deployment, routing and existing-data migration decisions. This review did not change origins or migrate browser data, and found no new bank-origin escape.

## Repeatable CI checks

[The security workflow](../../.github/workflows/security.yml) is configured for pull requests, pushes to `main`, a weekly schedule and manual runs. It adds:

- Full fetched-history Gitleaks scanning with redacted output.
- Strict NuGet restore audits for all four projects, including transitive packages and low-severity advisories. Explicit public package/audit sources, fresh HTTP retrieval and warnings-as-errors prevent an unavailable advisory feed from looking like a clean result.
- cargo-audit for all three first-party Rust lockfiles. Known vulnerabilities fail the job; informational maintenance warnings remain visible.
- A locked npm audit inventory for MSAL and Pyodide. An inventory check verifies the shipped MSAL bytes and detects drift in the Ledger runtime and Pages test-runtime references.
- The CSV export regression and inventory guard tests.
- CodeQL C# and JavaScript/TypeScript analysis using the extended security query suite.

GitHub Actions are pinned to commit IDs. Downloaded Gitleaks/cargo-audit executables have pinned versions and SHA-256 checks. Checkout credentials are not persisted, default permissions are read-only, and only the CodeQL job requests security-event upload permission. Installation of npm inventory packages disables lifecycle scripts.

These are separate security checks. They do **not** change the existing Pages deployment dependencies, branch protection or repository rulesets. CodeQL uploads findings; successful analysis execution alone does not mean that it found no alerts. Review its results after the workflow first runs.

GitHub reported Dependabot alerts disabled during the read-only status check. Secret-scanning configuration could not be verified with the available API access. No remote security settings were changed. The new local workflow is not evidence of an already-completed hosted CodeQL scan.

## Scope limits and next work

Bootstrap `5.3.3` is used as CSS in the first-party shells; the npm inventory is not presented as a complete site-wide software inventory.

Live bank/provider endpoints were not probed, and current Azure secrets, Key Vault, firewall, SQL backup retention and Entra settings were not inspected or changed. Historical configuration notes remain historical. No production financial actions, real-data imports or browser-storage migrations were performed.

Follow-up: publish and inspect the new security workflow's results; address any CodeQL findings; plan the PDF time-library migration and sensitive-tool origin isolation; and decide separately whether to enable hosted vulnerability alerts and make security checks required before deployment.

Each named editor creates a dedicated module worker with a relative, same-origin URL and keeps its `Worker` reference in the editor instance. The reviewed message paths use that reference's dedicated channel, not an externally addressable `Window` message listener. ### Pages deployment gate

The [Pages workflow](../../.github/workflows/pages.yml) now calls the local [reusable security workflow](../../.github/workflows/security.yml) on main pushes, pull requests and manual runs. GitHub resolves a [same-repository reusable workflow](https://docs.github.com/en/actions/how-tos/reuse-automations/reuse-workflows) from the caller's commit. Production deploy requires a successful build, a successful security call and a matching commit SHA emitted only after Gitleaks, NuGet, Rust, JavaScript and CodeQL all succeed. Failure, cancellation, skipping or a missing or mismatched output blocks deployment. Pull requests and manual runs on branches other than main verify without deploying; the standalone weekly and manual security runs never deploy.

This gate checks execution, not the absence of CodeQL alerts. Open alerts still require triage. Repository rulesets, branch protection, and the Pages environment settings were not changed. Verify both workflows' hosted results on the first run containing this change.
